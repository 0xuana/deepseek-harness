# @deepseek-ai/dsh-agent-model

[English](README.md) | 中文

## 概述

为 Session 的下一个模型步骤选择提供方、模型与可选的推理强度。记录的选择在恢复后保留，已经开始准备的步骤则在重试期间继续使用捕获的选择。空白 Session 可以继续跟随 Agent 的实时默认值。可选的作用域插件会在另一条路由继续对话时向模型添加提示。

<a id="use-this-package"></a>
## 使用本包

基础 bundle 与最小 SDK bundle 会挂载选择提供方。自定义组合将其与 Session 投影注册表一起挂载；消费方注入 `agentModel`。

```yaml
- name: '@deepseek-ai/dsh-session'
- name: '@deepseek-ai/dsh-session-projection'
- name: '@deepseek-ai/dsh-agent-model'
```

提供方没有配置字段。`ctx.agentModel.resolveForNextStep(agent)` 依次读取待用选择、最近请求的选择和 `agent.options`；返回独立的值，各来源均未提供完整路由时返回 `undefined`。读取不会启动步骤或固定选择。没有选择或请求记录的 Session 会继续读取 Agent 的实时回退选项。

`select(agent, selection)` 记录完整选择，已有相同选择时不重复记录。与 options 回退值相同的显式选择仍会记录。省略推理强度表示跟随适配器默认值；此操作不会补齐默认值、检查模型目录或保存部署默认值。记录用户选择前先使用 `llm` 校验。Session 追加失败沿用 Session 已有的失败保证。

普通恢复保留记录中的选择。入口若明确覆盖它，在未发布的 Agent setup 中调用 `applyConfiguredRoute(agent, selection)`。此方法要求完整的配置路由，仅在路由不变且声明省略强度时继承现有显式强度。要明确恢复为适配器默认强度，调用不带强度的 `select()`。

要为一个 Agent 启用切换提示，从 `@deepseek-ai/dsh-agent-model/notice` 导入 `* as ModelSwitchNotice`，并在该 Agent 的 setup 回调中等待 `agentCtx.plugin(ModelSwitchNotice)`。所属作用域在释放时移除监听器。此注册不会向其他 Agent 添加提示。

<a id="understand-the-implementation"></a>
## 理解实现

<details>
<summary>实现内部机制——点击展开</summary>

提供方等待一个纯折叠注册完成后再发布 Service，并在消费方清理期间保留返回的读取句柄。Session 日志是权威记录；投影注册表拥有折叠缓存，选择服务不再保存另一份每个 Agent 的选择。请求头仅清除与其匹配的待用选择，并从保留的选择中省略由适配器默认补齐的强度。循环在组装前捕获独立的选择，并在重试期间持有该步骤快照。

- [`src/service.ts`](src/service.ts) 负责选择读取、替换与配置路由应用。
- [`src/projection.ts`](src/projection.ts) 负责持久折叠和客户端视图；[`src/types.ts`](src/types.ts) 导出折叠状态与客户端视图类型。
- [`src/index.ts`](src/index.ts) 负责投影注册与服务生命周期。
- [`src/notice.ts`](src/notice.ts) 比较已准备步骤的路由与上次请求头，不读取更新的待用选择。

</details>

<a id="model-experience"></a>
## 模型体验

### 可选的路由切换提示

#### 模型看到什么

作用域提示插件会在已接纳请求步骤的准备路由不同于上次请求时，追加 `[model changed: assistant turns above this point were generated by <previous>; the session continues with <next>]`。仅跨提供方切换时在标签中包含提供方。初始请求、只改变强度、被拒绝的步骤和不发出请求的空决策均不添加提示。请求头持久化前失败会保留先前路由，所以下一个请求步骤会再次收到提示。

#### Token 影响

每条被接纳的提示都将文本加入保留的用户消息历史。选择事件本身不添加提示词文本。

#### KV Cache 影响

提示追加到历史，不替换先前消息。切换请求模型可能使先前模型的缓存无法复用；缓存是否可用仍由提供方决定。

## 已知限制与延后工作

<a id="known-limitations-and-deferred-work"></a>

- **可用性由调用方负责**——记录选择不代表适配器可用。入口校验用户选择，请求准备解析实际适配器与默认值。
- **部署默认值独立管理**——改变一个 Session 不会为其他 Session 保存默认值；该策略属于入口与默认模型服务。
