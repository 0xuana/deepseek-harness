# @deepseek-ai/dsh-agent-model

English | [中文](README.zh.md)

## Summary

Choose a provider, model, and optional reasoning effort for a Session's next model step. Recorded choices survive resume, while a step already being prepared keeps its captured choice through retries. Empty Sessions can continue following their Agent's live defaults. An optional scoped plugin tells the model when a different route continues its conversation.

<a id="use-this-package"></a>
## Use this package

The base and minimal SDK bundles mount the selection provider. Custom compositions mount it alongside the Session projection registry; consumers inject `agentModel`.

```yaml
- name: '@deepseek-ai/dsh-session'
- name: '@deepseek-ai/dsh-session-projection'
- name: '@deepseek-ai/dsh-agent-model'
```

The provider has no configuration fields. `ctx.agentModel.resolveForNextStep(agent)` reads the pending selection, then the latest request's selection, then `agent.options`; it returns a detached value or `undefined` when none supplies a complete route. Reading neither starts a step nor pins a choice. A Session without a selection or request continues reading its Agent's live fallback options.

`select(agent, selection)` records the complete choice unless an equal choice is already recorded. An explicit choice equal to the options fallback is still recorded. Omitted reasoning effort follows adapter defaults; this operation does not materialize defaults, check catalog membership, or save the deployment default. Validate user choices with `llm` before recording them. Session append failures retain the Session's existing failure guarantees.

Ordinary resume preserves recorded selection. An entry point that explicitly overrides it calls `applyConfiguredRoute(agent, selection)` during unpublished Agent setup. It requires a complete configured route and inherits an existing explicit effort only when the route is unchanged and the declaration omits effort. Use `select()` without effort to explicitly return to adapter defaults.

To enable switch notices for one Agent, import `* as ModelSwitchNotice` from `@deepseek-ai/dsh-agent-model/notice` and await `agentCtx.plugin(ModelSwitchNotice)` inside that Agent's setup callback. The owning scope removes its listener on disposal. Other Agents receive no notice from that registration.

## Understand the implementation

<details>
<summary>Implementation internals — click to expand</summary>

The provider awaits registration of one pure fold before publishing its Service and retains the returned reader through consumer teardown. The Session log is authoritative; the projection registry owns fold caches, and the selection service holds no second per-Agent choice. A request header clears only its matching pending selection and omits adapter-defaulted effort from the retained choice. The loop captures a detached choice before assembly and owns that step snapshot through retries.

- [`src/service.ts`](src/service.ts) owns selection reads, replacement, and configured-route application.
- [`src/projection.ts`](src/projection.ts) owns the durable fold and client view; [`src/types.ts`](src/types.ts) exports the fold state and client view types.
- [`src/index.ts`](src/index.ts) owns projection registration and service lifetime.
- [`src/notice.ts`](src/notice.ts) compares the prepared step route with the previous request header without reading a newer pending choice.

</details>

<a id="model-experience"></a>
## Model Experience

### Optional route-switch notice

#### What the model sees

The scoped notice plugin appends `[model changed: assistant turns above this point were generated by <previous>; the session continues with <next>]` to an accepted request step whose prepared route differs from the previous request. Labels include providers only for a cross-provider switch. Initial requests, effort-only changes, rejected steps, and empty no-request decisions add nothing. A failure before header persistence leaves the previous route unchanged, so the next request step receives the notice again.

#### Token effect

Each admitted notice adds its text to retained user-message history. Selection events themselves add no prompt text.

#### KV Cache effect

Notices append to history without replacing earlier messages. Switching the requested model may prevent reuse of the previous model's cache; cache availability remains provider-owned.

## Known Limitations and Deferred Work

<a id="known-limitations-and-deferred-work"></a>

- **Availability is caller-owned** — recording a choice does not prove an adapter is available. Entry points validate user choices, and request preparation resolves the actual adapter and defaults.
- **Deployment defaults are separate** — changing a Session does not save the default for other Sessions; that policy belongs to the entry point and default-model service.
