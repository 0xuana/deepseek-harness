# @deepseek-ai/dsh-experimental-creation-recommendations

[English](README.md) | 中文

## 概述

用户明确或隐含地表达清晰的可复用界面需求，或当前任务已得到明显可复用的结果时，Agent 先回答，再视情况在本轮末尾提供一张可选创建卡片。用户可修改建议位置，再选择创建。后台 Creator 生成一个新插件并安装到配置档案；保留用于确认继续使用，撤销则移除该插件。

## 使用本包

打开插件 → 更多 → 实验性插件，启用个性化页面。内置配置档案默认不启用此插件。启用后在插件一级页显示，关闭后仅保留在二级页。它没有配置字段。用户明确指定的位置优先；否则 Agent 根据作用范围和交互方式推荐：

| 位置 | 用途 |
|:--|:--|
| `sidebar-right` | 与 Session 关联的查看器、编辑器或 Context 检查，显示在对话右侧。 |
| `page` | 与 Session 关联的流式输出或交互，在对话、轨迹旁新增 Tab。 |
| `sidebar-left` | 全局功能：左侧入口打开主区域独立页面，不显示对话、轨迹 Tab。 |

左侧入口和全局页面属于同一落点，也适用于全局流式工具。默认选位先区分全局与 Session；Session 内的流式输出或交互优先使用顶部 Tab，其余查看器、编辑器放右侧栏。从结果顺带推荐的页面保留已知数据范围；当前 Session 的查看器默认放右侧。仅当缺失的范围信息会改变结果时才澄清。

卡片还提供“自行撰写”。手写位置优先于早先的位置描述，并保存在接受记录中。Creator 按需读取三种位置指南，通过现有 DSH 扩展点实现，不增加第四种 Slot，也不额外调用路由模型。无法支持的位置应报告失败，不得悄悄替换成其他位置。空白或超过 1,000 字的输入在启动子任务前被拒绝。

即使未安装或未启用插件推荐实验，个性化页面也可独立使用。它为工作和个人任务规划可复用界面，不局限于 DSH 功能。只有需求符合页面规划条件后，Skill 才使用当前官方插件目录避免重复创建。询问现成功能不加载此规划 Skill。匹配到现有插件时说明它在插件页的入口；同时启用插件推荐实验后，也可以通过 `suggest_plugin` 推荐该插件。两个实验共用每轮最多一张卡片的限制。

面对多个独立需求，指引要求在调用工具前从个性化页面和插件推荐中选定一项。优先遵循用户明确指定的顺序，否则先推荐现成插件。其余需求在正文说明。仅当缺失信息会改变功能结果时才澄清，不从另一个愿望推断用途或数据来源。被拒绝的建议不会生成卡片，也不会安排未来自动出卡。选定现成插件后，无需为未选中的创造需求查询目录。这些语义指引补充 Host 每轮最多一张成功卡片的限制，不引入两个实验之间的依赖。

### 操作结果与恢复

下一条人工消息被接纳时，尚未创建的方案立即失效，包括对方案的追问。卡片保留“已失效”状态并移除创建操作，Host 也拒绝旧卡点击。刷新、切换页面和后台通知不触发失效。已经开始的任务保留进度和重试入口。失效状态由已有用户消息事件派生，不新增持久化操作记录。

创建要求当前会话是活动的根会话，并且连接有权修改配置档案。生成阶段可取消，子任务清理完毕后才能重试。安装开始后显示“正在安装”，等待已接纳的操作结束。关闭或离开会话不会卸载已完成的插件。重新连接后会恢复操作记录；重试之前会对照已安装插件检查中断或结果不明的创建。移除失败时保留已有记录和实际生效结果，以便重试。卸载推荐插件会停止它负责的 Creator 任务和本地后续处理。已接纳的配置变更由插件管理器负责，可能在重载后完成；重新打开会话时先检查安装状态再允许重试。已安装插件仍然保留。恢复只确认安装，不根据配置中的开启标记推断运行时已生效。

下一次自然发起的模型请求会收到各张已变化卡片尚未告知模型的最新状态。状态更新不会唤醒对话，也不授权其他动作。Session 投影只在状态上下文写入日志后确认送达，因此取消、重载和重新打开会话都保留未送达的更新。一次请求之前发生的多次后台变化合并为最新记录。

## 实现原理

<details>
<summary>实现细节 — 点击展开</summary>

Host 入口是普通函数插件，在 `apply` 内通过 `ctx.plugin` 组装内部 `creationRecommendations` Remote service。该 service 负责本功能的状态、effect 生命周期和类型化按钮通信，不作为可替换能力单独暴露为 YAML 条目；`dsh-base` 不增加 service。关闭功能插件时一并卸载内部 service、工具和监听，并清理其负责的异步工作。此结构沿用 `command-feedback` 组装 `sessionFeedback` 的现有方式。

插件通过内部函数注册唯一的 `suggest_action` 工具。封闭的请求 schema 选择 `create_personalized_page`；同步 `prepare` 回调只返回持久化 JSON，不执行动作。成功的原生和 PTC 调用记录 `{actionCard: {action, callId, data}}` 元数据。插件自行提供卡片渲染和点击处理；卸载时移除工具，并拒绝已失效的调用。工具命名和元数据不绑定创建业务，但本实验不增加卡片 service、公共注册中心或独立 Loader 条目。其他动作类型及跨插件注册等到第二个实际消费者出现、契约明确后再设计。

Host 预留新包名，通过 `subagents` 启动已有的 `cordis` 预设，传入完整需求和选定位置。子 Agent 在父会话原工作区的 `.dsh-created-plugins/<id>` 下生成文件，保留委派时的文件权限。Host 校验包身份和仅允许新增的普通 YAML 或 JSON 补丁，将结果复制到配置档案的 `created-plugins` 目录并再次校验，再调用 `pluginManager.installBundle`；安装后的插件不依赖原工作区。补丁只能添加该新包自身且名称唯一的非分组条目；不接受自定义 YAML 标签、别名或 include。每个条目必须能解析到已构建的 JavaScript 文件。相对符号链接必须留在包内，复制时保留原目标。Session 投影保存建议和操作记录。恢复失败时仍可打开会话，卡片显示结果不明；重试必须先检查配置档案。后台完成结果写入重新打开的当前 Session 实例。并发点击合并为一次操作；工具守卫在每轮为 `suggest_action` 和 `suggest_plugin` 合计预留最多一条推荐。

Creator 收到完整方案、优先于早先位置描述的用户最终选位，以及本插件随包提供的位置指南绝对路径。指南补充 `cordis-plugin-development`，不依赖更新版预设包；Creator 按需读取注册、状态和卸载指引，再检查当前 API。卸载时应移除自己的界面和页签，保留其他内容；这是生成代码的要求，不属于静态包校验。[意图用例](tests/fixtures/intent-cases.json)用于真实模型观察，与确定性的服务测试分开。

页面基于已有结果创建时，方案还可携带 `initialContent`：所需的原始行、数值及其对应关系，与卡片显示的简短方案分开保存。它可从日志恢复，并作为数据交给 Creator。子 Agent 不继承主对话，因此主 Agent 必须补齐必要内容，同时避免复制无关历史。省略此字段表示未提供已有内容。交接会完整保留提交的文本，但不能校验模型是否包含了所有相关事实。用户自行添加内容时，可以先给空白页面方案，无需先补齐旧资料，但不得承诺自动导入聊天。明确要求预填而原始内容缺失时，应先澄清。

## 模型体验

### 创建建议

#### 模型看到的内容

已有 `skill` 工具在用户明确或隐含地表达了清晰的可复用界面需求，或任务结果需要反复查看、更新时加载 `personalized-pages`。简短目录描述这些适用条件，不逐项列举插件场景，也不新增公共 system prompt。加载后返回规划和位置指引，以及供查重的当前官方插件名称、描述和启用状态。目录不负责触发规划，也不是内置 UI 的完整清单。询问现成功能、普通开发、引用中的愿望、只讨论、已拒绝及一次性请求不需要加载或出卡。已有能力合适时不再提重复页面方案；无法确认的细节保持明确。唯一新增工具是 `suggest_action`，其结构化 `request` 选择 `create_personalized_page`，包含 `title`、用一至三句话描述用户要求或必需行为的 `brief` 和 `slot`，并可用 `initialContent` 交接已有数据；不要求负责人等业务字段。工具回执明确说明尚未开始执行。先给方案、只读模式仍允许提交建议。只有点击创建才后台启动 Creator；Agent 不等待、轮询、声称已安装或要求刷新、报告完成。普通回答仍是文本，不解析 Markdown/JSON 回答协议来生成卡片。

#### Token 影响

启用后增加一个共享卡片工具声明和一条简短 Skill 目录记录。完整策略和当前插件描述仅在已有 `skill` 工具加载时进入上下文。一次普通创建推荐需要一次 Skill 加载和一次 `suggest_action` 调用。策略要求复用本轮已读取的目录，避免重复查询。只有用户接受创建后，才会产生后台 Creator 调用。卡片的信息按钮说明生成可能耗时较长、消耗大量 token；查看说明不会启动任务。

#### KV Cache effect

Skill 内容和建议元数据追加到对话；加载 Skill 不改写公共 system prompt。开启或关闭本实验会添加或移除相应工具声明。安装生成的插件可能改变后续工具声明和缓存复用。变化后的卡片记录会以简短状态通知追加到下一次请求；状态不变的卡片不重复增加上下文。这里复用已有的请求准备钩子，不增加工具或模型调用。

## 已知限制与后续工作

<a id="known-limitations-and-deferred-work"></a>

- 只支持新增插件；修改已有插件和恢复旧版本留待后续。
- 意图识别依赖模型语义。指引不强制工具选择或事实依据：Agent 仍可能多余地查看文件，或推断目录没有说明的能力。生成代码使用现有 Creator 权限执行，包校验不构成代码沙箱。
- 成功、失败、取消及撤销后均保留工作区源目录和配置档案副本。撤销移除已安装插件及其界面，不删除这些文件。卡片会说明源码位于原工作区的 `.dsh-created-plugins/` 目录。历史记录不会持续跟踪手动插件变更。

- 暂不自动超时取消创建。关闭 Session 或关闭此实验会停止它负责的生成任务；已接纳的安装继续由插件管理器负责。
