# Agent Note: 应用布局之外的图片拖放归属

Status: implemented

[English](2026-10-19-image-drag-plugin-ownership.md) | 中文

## Problem

图片拖放跨越会话图片、侧栏预览和输入框接收区。拖动期间原始文件必须在源组件卸载后继续保留，发起操作的面板关闭后失败提示也必须可见。应用根部的图片 Provider 把功能状态放进布局，并使独立图片入口依赖未声明的 React 祖先组件。

## Decision

[图片拖放插件](../../../../packages/client/ui-image-drag/README.zh.md) 持有浏览器传递令牌、原始文件、桌面桥接选择和临时失败提示。消费方通过 slot 或 Factory 注入接收范围明确的回调。插件通过 `shell.overlay` 注册提示，布局只声明通用插槽，不依赖图片功能。共享图片原语通过显式操作属性负责准备和手势处理。

## Alternatives considered

**根部 React Provider。** 它能保留传递生命周期，但会把图片专属组合放进布局包，并对 slot 注册隐藏依赖。把同一个包裹组件移到渲染器，只会把功能耦合转移到另一个通用模块。

**每张图片独立持有状态。** 这能避免共享组合，却不能在源组件卸载后交付保留文件，也不能在面板关闭后继续显示延迟到达的失败提示。

## Consequences

一个插件生命周期管理传递状态与窗口监听器。独立渲染根可以共享传递，而不共享 React 祖先组件。自定义组合必须加载服务并声明反馈插槽，自定义图片 Factory 注册必须提供所需回调。插件卸载会移除提示并清除保留的传递状态。通过 Loader 启动的浏览器场景覆盖实际产品组合，定向测试验证跨根交付和延迟失败提示。
