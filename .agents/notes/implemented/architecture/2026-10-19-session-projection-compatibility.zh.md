# Agent Note: 已弃用的投影注册兼容接口

Status: implemented

[English](2026-10-19-session-projection-compatibility.md) | 中文

## Problem

现有外部插件使用投影注册返回的 disposer，并通过 registry 读取状态。异步保留读取句柄改善了获取和清理所有权，但删除这些运行时操作会迫使彼此无关的插件一起迁移。

## Decision

[保留读取句柄的决策](2026-10-12-session-projection-registration-handles.zh.md)仍是常规 API。注册返回值兼容 Promise 且可调用：等待它得到句柄，调用它保留旧的释放操作。这个可调用值就是原有 Cordis effect disposer，使组合 effect 能接管其所有权并控制释放顺序。按键读取作为已弃用的运行时 API 保留，返回类型为 `unknown`。TypeScript 消费方仍需迁移声明；旧宿主状态映射和泛型签名不再恢复。每个 registry 实例拥有针对旧注册和按键读取的一次性控制台警告；警告状态不归进程全局对象所有。

定义安装保持同步，句柄交付保持异步。registry 观察获取结果和现有 `fiber.await()` 的结果，不修改 Cordis，也不延迟激活。启动结束后，未被观察的注册拒绝会被记录，并通过现有 API 卸载调用方插件。这会停止故障插件，但不会把注册加入激活 Promise。显式观察返回 Promise 的插件仍负责处理错误，包括在异步初始化稍后才等待注册的情况。

这部分取代了先前决策中无条件迁移的要求。保留的句柄仍可在释放后折叠事件，按键读取仍在最后一次释放后失去访问，新代码使用私有句柄或所属领域服务。同步 `try/catch` 无法捕获异步获取失败。兼容性依赖当前同步安装定义的实现；引入异步准备时，需要重新处理在激活前读取的旧消费方，不能静默返回不完整状态。

## Alternatives considered

**要求所有外部插件立即迁移。** 即使插件只在初始化期间注册并在激活后读取，也会让保留读取句柄的变化成为整个部署需要协调的事项。

**返回 disposer 的新包装函数。** Cordis 组合按原始返回值身份接管 effect。包装函数会让原注册继续独立归属，从而使 owner 卸载在组合清理结束前释放它。

**自动延后所有 effect 或事件监听器。** 这些操作已有同步消费方和初始化期间的观察方。兼容要求属于投影获取；改变无关 effect 的时机会造成更大范围的迁移。

## Consequences

旧插件可以独立迁移，新代码保留显式异步获取。兼容层保留运行时调用和每个 registry 一次的诊断。定向测试覆盖现代错误恢复、忽略拒绝后的报错与卸载、可调用与组合释放、获取期间 owner 卸载，以及独立的警告所有权。真实 Loader 子进程通过包入口运行保持旧写法的插件，并验证读取结果和控制台警告。
