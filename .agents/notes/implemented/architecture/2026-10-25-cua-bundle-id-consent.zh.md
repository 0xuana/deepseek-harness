# Agent Note: 按 Bundle ID 共用 macOS 应用授权

Status: implemented

[English](2026-10-25-cua-bundle-id-consent.md) | 中文

## 问题

用户安装同一应用的多个版本时，希望对这个软件只做一次权限决定。可执行文件路径会拆分这些决定，签名检查也会让未签名的开发版应用无法保存长期授权。

## 决策

macOS 应用授权使用原生应用提供的、区分大小写的完整 Bundle ID。helper 将 `macos:bundle-id:` 和该标识连接后计算摘要，生成 `CuaApplicationId`。安装路径、版本和签名不区分授权。会话决定和长期许可保留[profile 授权存储](2026-10-19-cua-profile-consent-storage.zh.md)规定的范围和撤销行为。

本决策取代[应用授权](2026-09-26-cua-application-consent.zh.md)中的可执行文件和签名身份选择，原记录仍负责执行检查与用户决定。没有非空 Bundle ID 的运行中应用保留进程实例许可，待启动应用使用可执行文件内容身份，两者都不能获得“始终允许”。原生进程、可执行文件位置和窗口检查继续把每个句柄绑定到所选目标。启动检查从磁盘重新读取 Bundle ID 和可执行路径，但不为具有 Bundle ID 的应用计算可执行内容指纹。因此，在相同路径下替换内容且保留相同标识时，许可仍会沿用，包括等待用户批准期间的替换。

身份前缀将新授权与旧的路径和签名摘要分开。旧授权仍可撤销，但不能授予新 Bundle ID 身份访问权限；许可覆盖其他安装副本前，需要用户重新决定。

## 考虑过的替代方案

**Bundle ID 加路径。** 可以区分安装副本，但用户希望共同授权的多个版本仍需分别确认。

**验证签名身份。** 可以区分发布者，但没有签名或验签失败时无法保存长期授权。发布者身份验证不属于本项应用管理规则。

## 后果

声明相同 Bundle ID 的其他程序会继承许可，包括通过其他已授权模型工具创建或修改的程序。最坏后果是在应用已有数据和能力范围内，读取或控制用户未单独批准的程序。模型不能在 CUA 请求中提交授权身份，该身份由原生 helper 从实际选中的应用读取。不同 Bundle ID 仍需分别授权，即使用户将它们视为同一产品的不同版本。

撤销作用于同一标识的所有安装副本。测试覆盖未签名副本、不同标识、缺少标识、启动前后身份一致、多个句柄共同撤销，以及不扩大旧授权。
