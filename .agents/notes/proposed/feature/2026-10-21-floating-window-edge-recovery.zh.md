# Agent Note: 悬浮停靠面板的力导向边界收回

Status: proposed

[English](2026-10-21-floating-window-edge-recovery.md) | 中文

## 问题

dock kit 的悬浮面板就是客户端里的悬浮窗。`FloatLayer` 与保留式 `DockLayout` 渲染器通过同一个手势 hook `useFloatGestures` 以视口坐标绘制它们，右侧 Sidebar 嵌入了它们，因此同一套面板既运行在 Web 客户端中，也运行在 Desktop 窗口内。它们的拖拽一比一跟随指针，只有一个顶部下限（`--dsh-dockkit-float-top`，让标题栏保持在 Windows 标题栏之下）。因此面板可以被拖过左、右或下边界，直到标题栏够不着；视口缩小会把面板留在外面；新建面板的级联位置也可能落在小视口之外。期望行为是：面板被推过边界时可见地受到阻力，松手后以弹簧物理被拉回视口内，而不是像撞墙一样被挡住或被留在外面。

我们逆向分析了参考实现 Claude Desktop 2.42304.2，它没有这种行为。在 macOS 上它的 Quick Entry 是原生 Swift `NSPanel`；其二进制包含动画原语，但无法从中确认任何边界收回规则。Windows/Linux 上使用的 Electron 回退是静态的：输入防抖 750 ms 后做一次瞬时 `setPosition`，只裁剪右边界和下边界（触发边距为 0、目标边距为 30 DIP，因此首次修正在溢出量之外再跳 30），从不裁剪左边界和上边界。其主 bundle 中不存在 `spring` 符号；仅有的窗口运动工具是用于主窗口尺寸变化的 240 ms `easeInOutCubic` 边界补间、Electron 仅 macOS 可用的 `setBounds(bounds, true)`，以及 300 ms `cubic-bezier(0.16, 1, 0.3, 1)` 的 CSS 运动语汇。该行为必须被设计，而不是移植。

变更必须维持以下义务：面板标题栏始终可达；一个手势仍然只记录一条历史；遵循减弱动态效果；Sidebar 的持久化布局格式与所有嵌入方保持不变；运动足够确定，无需真实浏览器时钟即可测试。

## 提案

该行为完全位于 `packages/client/ui-dockkit` 内，在 `useFloatGestures` 及其调用的纯 engine 辅助函数中实现。由于两个悬浮渲染器都已从该 hook 取得矩形，Web 与 Desktop 同时获得该行为，不改动任何嵌入方、壳或持久化格式。

### 合法区域与显示位置

面板的合法区域是视口（`window.innerWidth` × `window.innerHeight`）加上既有的顶部下限：设置了 `data-windows-titlebar` 时为 Windows 标题栏高度加 20 px（原生全屏时为 20 px），否则为 0。当 `x` 位于 `[0, viewportWidth - width]` 且 `y` 位于 `[top, viewportHeight - height]` 时矩形合法。面板比区域更宽或更高时钉住最小边，使标题栏及其抓手留在屏幕上，多余部分悬在右侧或下方。

显示矩形是存储矩形在合法区域上的逐轴投影，在渲染时计算。存储矩形不会被改写：视口缩小时面板立即被推入，且不记录操作；视口再次变大时面板回到存储位置。本变更之前持久化下来、包含屏幕外矩形的布局无需迁移即在视口内显示。

### 带阻力的拖拽

移动手势照旧由手势起始矩形和指针位移计算期望矩形，然后逐轴拆分为合法投影与超出它的溢出量 `o`。预览矩形绘制在 `legal + sign(o) * K * |o| / (K + |o|)`，其中 `K = 120` px。该映射连续、在边界处斜率为 1、渐近于 `K`，因此面板起初会越过边界，指针走得越远阻力越大：

| 指针溢出（px） | 面板越过边界的位移（px） | 占溢出的比例 |
|---|---|---|
| 10 | 9.2 | 92.3% |
| 40 | 30.0 | 75.0% |
| 120 | 60.0 | 50.0% |
| 400 | 92.3 | 23.1% |

缩放手势把右下角钳制在合法区域内并保持 `FLOAT_MIN_SIZE`；缩放不加阻力，因为落后于指针的角看起来像坏掉的手柄。

### 松手与弹簧

松手时手势以合法矩形记录一次 `moveFloat`，因此历史与持久化始终存储合法位置。如果预览在合法区域之外，hook 继续绘制预览，用弹簧把它从松手位置动画到记录的位置，然后清除预览。在合法区域内松手则记录移动且不播放动画。

弹簧是欠阻尼的，因为它的回弹朝向内侧，始终合法：响应时间 0.32 s、阻尼比 0.72（`omega0 = 2 * pi / 0.32`）。初速度取拖拽最后 100 ms 的指针速度，上限 1500 px/s，因此甩过边界的面板比慢慢推过去的回来得更快。每轴更新为：

```
a = -omega0^2 * (x - target) - 2 * zeta * omega0 * v
v = v + a * h
x = x + v * h
```

积分器使用固定子步 `h = 1/480 s`。hook 中唯一的 `requestAnimationFrame` 循环把每帧经过的时间拆成等长且不超过 `h` 的子步，单帧钳制到 64 ms，帧间隔超过 250 ms 时直接跳到目标。当每轴距离在 1 px 内且速度低于 60 px/s，或经过 900 ms 后，它停止并绘制精确目标。从静止开始仿真，200 px 溢出在 367 ms 内稳定，向内过冲 6.9 px（3.5%），在解析上限 `exp(-pi * zeta / sqrt(1 - zeta^2)) = 3.8%` 之内；阻力把松手时的溢出限制在 120 px 内，因此真实松手稳定得更快。积分器是纯函数并接收 `dt`，因此 engine 保持不读取时钟的规则。

动画期间按下面板会取消动画，并从正在绘制的矩形开始新手势。每个面板最多运行一个动画，卸载该层会取消其帧请求。

### 减弱动态效果

`matchMedia('(prefers-reduced-motion: reduce)')` 匹配时，移动手势钳制在合法区域内且无阻力，松手时记录合法矩形且不播放动画。该规则只移除运动，从不移除合法性修正。

### 改动范围

实现只修改一个包 `@deepseek-ai/dsh-client-ui-dockkit`，其导出与 `DockIntents` 保持不变。

| 文件 | 变更 |
|---|---|
| `packages/client/ui-dockkit/src/engine/geometry.ts` | 新增合法投影与阻力映射 |
| `packages/client/ui-dockkit/src/engine/` | 新增 `spring.ts`：纯弹簧积分器及其稳定判定 |
| `packages/client/ui-dockkit/src/components/FloatLayer.tsx` | `useFloatGestures`：显示投影、阻力、松手弹簧、速度采样、减弱动态效果、帧循环与取消 |
| `packages/client/ui-dockkit/src/components/TabLayout.tsx` | 绘制 hook 给出的显示矩形而不是存储矩形 |
| `packages/client/ui-dockkit/tests/` | 几何、弹簧、`FloatLayer` 与 `TabLayout` 测试 |
| `packages/client/ui-dockkit/README.md` 对 | 在交互规则下补充边界规则 |

`ui-sidebar-right` 及其持久化布局 schema、`apps/web`、`apps/desktop`、共享基础组件与主题均不改动。不新增依赖。

## 测试计划

纯测试覆盖投影（内部、每条边、角、超尺寸面板、Windows 顶部下限）、阻力映射（连续、单调、边界处斜率为 1、以 `K` 为上界），以及固定时间步下的弹簧（轨迹确定、最终目标精确、向内过冲与解析上限相差不超过一个百分点、在 900 ms 截止时间内稳定、30／60／120 Hz 节奏鲁棒，以及 250 ms 停顿直接跳转）。

组件测试在 jsdom 中用假的 `requestAnimationFrame` 与时钟运行 `FloatLayer` 和 `TabLayout`：拖过每条边绘制带阻力的预览；松手恰好记录一次带合法矩形的 `moveFloat`；预览动画到该矩形后清除；动画中按下会取消动画并从绘制中的矩形开始；减弱动态效果下钳制且从不调度帧；视口缩放移动显示面板而不调用任何 intent；卸载取消帧请求。逐文件覆盖率门禁适用于每个改动的源文件。

在 Web 客户端中进行浏览器检查：把 Sidebar 悬浮面板拖过每条边与每个角、甩出去、在其下方缩放窗口，并在减弱动态效果下重复；PR 以 GIF 记录。Desktop 加载同一份客户端 bundle，因此在那里手动走一遍即可确认 Windows 标题栏下限。

不需要 keyless 录制会话快照：没有模型可见的变化，也没有新增 `SessionEventMap` 成员。文档门禁：`doc-sync`。

## 考虑过的替代方案

**在边界处硬钳制。** 在视口边界停住面板是成本最低的正确规则，但手感像撞墙，接触之前也感觉不到边界。它保留为减弱动态效果的路径。

**拖拽中钳制、松手时回弹。** 在边界处钳制拖拽，并把向外的指针速度转换为向内的回弹，能让每一帧都留在视口内。但它隐藏了用户推了多远，回弹因此没有可见的起因；阻力映射显示了推动，同时把溢出限制在 120 px 内。

**松手后的缓动补间。** 从松手位置开始的固定 240–300 ms 缓出补间可预测，但不携带速度，因此甩出与慢推的返回完全相同，补间中按下要么跳变要么重启。弹簧保持速度连续且可打断。

**存储屏幕外位置并在之后修正。** 记录松手矩形、在下一次渲染时修正，会持久化屏幕外位置，并让撤销恢复它们。记录合法矩形则保持每个手势一条历史且值合法。

**视口缩小时改写存储矩形。** 在缩放时通过操作移动面板会增加用户从未做过的历史条目，并在每次窗口缩放时改变持久化布局。渲染时投影无需二者即可得到相同的可见结果。

**原生始终置顶 OS 窗口。** 真正的 Electron 悬浮窗可以浮在其他应用之上，但只在 Desktop 上可行；Web 客户端完全无法做到，而且原生无边框拖拽不提供逐帧控制，因此阻力无法实现，弹簧只能在松手后启动。它是一个独立的产品决策，有自己的窗口、IPC 与平台工作，本 Note 不排斥它。

**动画库依赖。** 弹簧库会用一个静态链接包里的新依赖替换几十行的纯积分器及其测试。积分器还必须不依赖时钟，才能用于 engine 的确定性测试。

**放进 `ui-primitives` 的共享基础组件。** 把 hook 放进基础组件包会把改动扩大到第二个包，而目前没有第二个使用方。等另一个悬浮界面需要它时再迁移。

## 验收标准

- 把悬浮面板拖过任一视口边界时，它绘制在带阻力的位移处，越过边界不超过 120 px；减弱动态效果下改为钳制在边界处。
- 在合法区域外松手恰好记录一次矩形合法的 `moveFloat`，面板在 900 ms 内弹到该矩形，最终停在精确的记录位置。
- 这样的手势之后撤销一步即可恢复手势前的位置，持久化布局中从不包含记录时就不合法的矩形。
- 在合法区域内松手的行为与现在相同：一次操作，无动画。
- 动画期间按下面板会停止动画，新手势从屏幕上的矩形开始。
- 视口缩小时每个面板标题栏都留在屏幕上且不记录操作；视口变大时面板回到存储位置。
- 在 Windows 标题栏下，标题栏与现在一样至少保持在其下方 20 px。
- 除 `@deepseek-ai/dsh-client-ui-dockkit` 外没有其他包改动，其导出与 `DockIntents` 不变。

## 风险

**每个动画帧一次渲染。** 弹簧通过 React state 更新预览，每帧成本与现在拖拽时相同，但承载重内容的面板在松手后最多会重渲染 900 ms。如果测量显示掉帧，循环可以直接在面板元素上写 transform，而不改变规则。

**视口变大后的弹性返回。** 被缩小窗口推入的面板会在窗口变大时回到存储位置。这是不改写存储矩形的预期结果，但期望面板留在被推到的位置的用户可能会感到意外。

**运动中的嵌入内容。** 面板可以承载接收指针事件的 webview 或 iframe。弹簧只在松手后运行，按下即取消，但会对自身移动作出反应的内容可能观察到最多 900 ms 的运动。

**触控仍未调优。** 阻力与速度采样来自 pointer 事件，适用于触控输入，但常量是针对鼠标或触控板调优的；README 已将触控列为未调优。
